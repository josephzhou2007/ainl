一、时间线

本仓库的代码
外部进程 / 网络服务

0 用户登录 Windows EAGER

Startup 文件夹（shell:startup）里的 ainl-autostart.lnk 被执行。它由 scripts/autostart_install.ps1 事先创建。

是「登录时」而不是「开机时」：密钥在 User 环境变量里，浏览器 profile 也属于这个用户。

powershell.exe 进程

-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File scripts\autostart.ps1

快捷方式 WindowStyle=7（最小化），不闪控制台。做完就退出。

▼

1 scripts/autostart.ps1：等网络 EAGER

  • 向 ~/.ainl/autostart.log 追加 autostart begin
  • 最多 30 次 × 间隔 4 秒解析主机名，记 network: True/False
  • 结果为 False 也继续往下走

系统 DNS 网络

解析 canvas.wisc.edu。刚登录时网络常未就绪，而 bot 的第一个调用就是 Canvas。

▼

2 scripts/browser_start.py EAGER

  • 先探测 127.0.0.1:9222/json/version：已在跑就什么都不做
  • 找 ms-playwright/chromium-*/chrome-win*/chrome.exe
  • DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP 脱离式启动，然后自己退出
  • autostart 再轮询端口最多 15 秒

python.exe（短命）→ chrome.exe ×N（常驻）进程

Playwright 自带 Chromium：--headless=new --remote-debugging-port=9222 --user-data-dir=~/.ainl/chrome-profile --disable-gpu --no-proxy-server 及三条防「被遮挡窗口停止渲染」的参数。

网络 命令行末尾带 WebAssign 首页地址，所以 chrome 启动瞬间就请求一次 www.webassign.net（重启后处于登出状态，无副作用）。

▼必须先有浏览器再起 bot：cookie 通道启动时要从它读 cookie

3 scripts/bot_restart.ps1 EAGER

  • 按完整命令行 *-m ainl.bot* 停旧 bot，绝不按进程名
  • 从 Windows User 环境读入：CANVAS_TOKEN TELEGRAM_BOT_TOKEN TELEGRAM_CHAT_ID GEMINI_API_KEY CANVAS_BASE_URL AINL_KEEPALIVE_MIN（只按名字，值从不打印）
  • 睡 6 秒，输出 bot processes: N 和 bot.log.err 末 2 行

python.exe -m ainl.bot（常驻，隐藏）进程

Start-Process -WindowStyle Hidden；stdout → ~/.ainl/bot.log，stderr → ~/.ainl/bot.log.err（logging 走 stderr，真正的日志在后者）。

同一个 bot token 只能有一个 getUpdates 消费者。

▼

4 bot/__main__.py → main()：配置与通道 EAGER

  • TelegramConfig.from_env()：缺变量 → 退出码 2
  • ApiSource.from_env() → channel.open_source()：读 ~/.ainl/channel.json；auto/token 且有 token → BearerAuth，不碰浏览器
  • 钉死的通道打不开 → 改回 auto 再试
  • canvas.whoami() 取时区

Canvas REST 网络

GET /api/v1/users/self/profile —— 启动阶段对 Canvas 的唯一一次请求。

仅 cookie 通道：MainThread 先起 Playwright 驱动、经 CDP 从 9222 读 cookie（auth_from_live_browser），再 GET /api/v1/users/self 探活。

▼

5 状态、菜单、保活线程 EAGER

  • BotState.load(~/.ainl/bot_state.json)：拿回 offset 与进行中的会话
  • Conversation(...)：只建对象，_webassign = None
  • tg.set_commands([...])：失败只告警
  • keepalive.start()：起 canvas-keepalive 线程，它先睡 30 分钟
  • 日志：bot up for chat … (tz …)

Telegram Bot API 网络

setMyCommands 一次：注册 /todo /restart /cancel /channel /timing /help。

▼

6 长轮询循环 EAGER · 持续

tg.get_updates(offset=state.offset, timeout=30)。网络异常：告警、睡 5 秒、继续。每条 update：更新 offset → conv.handle(u) → state.save()。

Telegram Bot API 网络

getUpdates 长轮询，只订阅 message 与 callback_query。

✔ bot 就绪。到这里为止（token 通道）：bot 没连过浏览器、没有 Playwright 驱动、没有 browser-N 线程、没调过 Gemini。
▼ 以下全部是 LAZY：第一条消息到达之后才发生

7 第一条消息：/todo LAZY

Conversation.handle() → _todo()。不是 TELEGRAM_CHAT_ID 的聊天直接忽略。是否 WebAssign 从 Canvas 返回的 external tool URL 判断，仍不开浏览器。

Canvas REST + Telegram 网络

planner 与 assignments 查询；sendMessage 回复列表。

▼学生回复一个 🧮 编号

8 第一次浏览器操作 LAZY

  • _wa() 才创建 WebAssign(launch_url=…)
  • link.dep_for() 先查 ~/.ainl/lti-map.json
  • browserthread.run() 创建 worker 线程 browser-1
  • pw.connect()：该线程首次 sync_playwright().start()，再 connect_over_cdp；连接缓存、不 close

Playwright 驱动 node.exe 进程

bot 的子进程，约 1 秒启动，每线程一个。经 WebSocket（CDP）attach 到 127.0.0.1:9222 的 chrome.exe。

▼

9 重建 WebAssign 会话 LAZY · 重启后第一次必走

webassign.py::_webassign_tab()：没有已登录标签 → 打开列表页仍登出 → launch_url() → canvas.sessionless_launch() → 浏览器打开启动地址 → 每秒检查是否到达 webassign.net。约 10 秒，无需密码。

原因：JSESSIONID、cmp-session-id 是会话级 cookie，浏览器进程一结束就没。

Canvas REST → LTI → WebAssign / Cengage 网络

bot 向 Canvas 要一次性启动地址（它是凭据，从不记录）；chrome.exe 打开它，经 LTI 跳转落到 WebAssign。之后读题、截图都由 chrome.exe 完成。

▼学生发来答案纸照片

10 读照片 LAZY

tg.download() → mathinput/pipeline.py::transcribe_with_consensus() → 默认读者 gemini-flash-lite → LaTeX → WebAssign 方言 MathML。整个系统唯一的 LLM 调用。

Gemini API 网络

generativelanguage.googleapis.com 的 generateContent；密钥 GEMINI_API_KEY 走请求头。

▼与消息无关、按时钟触发

11 保活 ping 启动后 30 分钟起，每 30 分钟

keepalive.ping()：在 canvas-keepalive 线程里起它自己的驱动、经 CDP 读活 cookie（读不到用磁盘快照），发一次请求，把轮换后的 cookie 写回快照。从不开窗口、从不要密码。

Canvas REST 网络

GET /api/v1/users/self。会话「死于无人问津，而不是死于年龄」。

看门狗（只在出事时）：某次浏览器操作超出预算 → 放弃当前 browser-N（Python 杀不了线程）→ 以子进程跑 browser_start.py --restart（仍然无窗口）→ browserthread.reset() → 下一次操作新建 browser-(N+1) 和新驱动。代价：WebAssign 会话又没了，步骤 9 再付一次。

四、检查与关闭

想做什么怎么做
确认启动成功看 ~/.ainl/autostart.log 末段：network: True → browser up on 9222 或 already running → bot processes: 1 → autostart end；然后在 Telegram 发 /todo
bot 没起来看 ~/.ainl/bot.log.err
关掉自启动scripts\autostart_install.ps1 -Remove，或 Win+R → shell:startup 删除 ainl-autostart.lnk（只影响下次登录）
Canvas 浏览器会话过期必须人在场：python scripts/browser_start.py --show，用 NetID + Duo 登录
不负责的事：登录之前不启动；Canvas 会话过期需要人登录；断电后第一次 WebAssign 操作多约 10 秒；没有守护进程 —— bot 启动失败或崩溃后不会被自动拉起，要等下次登录或手动运行 scripts\bot_restart.ps1。
