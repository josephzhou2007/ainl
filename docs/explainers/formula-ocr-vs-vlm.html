公式 OCR 模型 vs. 通用视觉语言模型：手写数学答案转写的技术差异

面向「手写微积分答案照片 → LaTeX → WebAssign 提交」这一用例，解释纯公式识别模型（Pix2Text、pix2tex、UniMERNet、Nougat、TrOCR 类）与通用 VLM（Gemini Flash、Qwen-VL、Claude / GPT 视觉）在架构、训练数据与行为上的根本区别，以及为什么这个区别决定了我们的流水线设计。

1. 公式 OCR 的架构：编码器 → 解码器 → LaTeX token

所有主流的公式识别（Mathematical Expression Recognition, MER）模型都是同一个骨架：一个视觉编码器把图像压缩成一串特征向量，一个自回归 Transformer 解码器逐个吐出 LaTeX token。这条路线由 Deng 等人 2017 年的 im2latex 工作确立（当时是 CNN + RNN + 注意力）[1]，此后编码器换成 ResNet / ViT / Swin，解码器换成 Transformer，但任务定义没变：输入一张公式图，输出等价的 LaTeX 字符串。

训练数据与「先验」

训练语料是成对的 (图像, LaTeX)：im2latex-100k（约 10 万条从 arXiv 源码渲染出来的印刷公式）[1]、CROHME（在线手写公式竞赛数据，含笔迹轨迹和离线位图，规模仅万级）[2]、以及各家自行合成的渲染数据。因为解码器只见过 LaTeX 序列，它学到的「语言先验」仅限于 LaTeX 语法本身——例如 \frac{ 后面大概率跟一个 }，^{ 之后常见单个字符。它不知道 ∫₀¹ x² dx = 1/3，因此也不会因为学生写了 = 1/2 而「纠正」它。

三个代表性实现

  • pix2tex / LaTeX-OCR[3]：ViT 编码器（前面接一个小 ResNet 做局部特征），解码器是 GPT-2 风格的 Transformer，用 im2latex 系列印刷数据训练。模型权重约百 MB 量级，CPU 上可以推理。它是最典型的「印刷优先」模型。
  • Pix2Text[4]：不是单个模型而是一条流水线——先跑版面分析 / 公式检测（MFD）把页面切成文本块、行内公式、独立公式，然后对每个公式裁剪块跑公式识别（MFR，基于 TrOCR 架构改造），文本块走普通 OCR，最后按位置拼回 Markdown / LaTeX。它更适合整页作业，而不只是一张公式。
  • UniMERNet[5]：上海 AI Lab 的「通用」公式识别器，基于 Donut / Nougat 式的 Swin 编码器 + BART 类解码器。关键贡献是 UniMER-1M 数据集，把印刷简单、印刷复杂、屏幕截图、手写四个域混在一起训练，并加入 Length-Aware Module 处理长公式。四个域中的 HWE（手写）子集是它区别于 pix2tex 的地方。

Nougat[6]（Meta）和 TrOCR[7]（微软）属于同一家族：Nougat 是「整页 PDF → Markdown+LaTeX」的 Swin + BART 编解码器，其公式部分本质上就是上面的骨架；TrOCR 是「ViT/BEiT 编码器 + RoBERTa 解码器」的文本行 OCR，Pix2Text 的 MFR 就是在它上面改的。

共同点：小（几十到几百 MB）、单一任务、无指令跟随、词表封闭、在 CPU / Apple Silicon 上可以做到亚秒级推理。

2. VLM 的架构：视觉编码器 → 投影层 → 大语言模型

通用视觉语言模型（Gemini Flash、Qwen2.5-VL、Claude、GPT-4o 等）的结构表面上也是「编码器 + 解码器」，但解码器换成了几十亿到上万亿参数的通用 LLM，中间靠一个投影层（MLP、Q-Former 或 Perceiver Resampler）把图像 patch 特征映射到 LLM 的词嵌入空间。开源模型如 LLaVA、Qwen-VL 的结构是公开的[8]；闭源模型细节未公开，但公开论文与技术报告表明整体范式一致。

三个决定性差异：

  1. 训练目标不同。公式 OCR 只优化「复现图中的 LaTeX」；VLM 优化的是「在图文上下文下生成人类偏好的回答」。转写、解题、批改、总结在同一个模型里共享参数。
  2. 先验强度不同。LLM 在预训练阶段见过海量数学文本，它「知道」∫₀¹ x² dx = 1/3。这个知识在解题时是优点，在转写时是干扰源。
  3. 可控性靠 prompt。公式 OCR 不接受指令，行为是确定的；VLM 的行为由 prompt 和采样温度共同决定，同一张图换个措辞可能得到不同输出。

3. 关键行为差异：「转写」还是「理解后改写」

把两类模型放到同一张含错误的手写答案上，差异最明显。

公式 OCR 的失败方式：显式的

公式 OCR 没有语义先验，所以它的错误是「感知层」的：把 a 认成 \alpha、漏掉一个上标、在笔迹粘连处输出一串重复 token 或不匹配的花括号。这些错误往往可以被检测——LaTeX 解析失败、括号不平衡、token 重复、解码器输出的每步概率很低——因此可以触发降级或人工确认。

VLM 的失败方式：静默的

VLM 的错误可能是「语义层」的：它读出了 = \frac{1}{2}，但解码器在语言先验的推动下生成 = \frac{1}{3}，输出的 LaTeX 完全合法、看起来完全合理，没有任何可检测的异常信号。这不是假设。Seong 等人 2026 年用 FERMAT 数据集（AI4Bharat 构建的 2200 余份含刻意引入错误的手写数学解答，ACL 2025）[9]系统测量了 15 个 VLM 在多行手写数学 OCR 中的「过度纠正」行为，结论是：42%–66% 的转写至少含一处模型覆写了学生原始内容的情况，从 Llama 3.2 11B 的 42.1% 到 Qwen2.5-VL 32B 的 66.2%，GPT-4o、Gemini 2.5 Flash 也在被测之列[10]。作者据此提出 PINK 指标，专门惩罚「转写得分高于原文得分」的不忠实输出。

为什么这对我们是致命的。我们的流水线把转写结果作为学生自己的答案提交到 WebAssign。如果 VLM 把错误答案「修正」成正确答案，会出现三个问题：(a) 提交的不是学生写的东西，违反了学术诚信的基本前提，也违反我们「不替学生作答」的边界；(b) 学生得到了错误的正向反馈，学习信号被污染；(c) 从日志上看不出任何异常——LaTeX 合法、得分正确。反过来，VLM 也可能把正确答案「简化」成等价但形式不同的表达（\frac{2}{4} → \frac{1}{2}，x^2+2x+1 → (x+1)^2），而 WebAssign 的某些题目要求特定形式。逐字转写（verbatim transcription）不是可选项，是需求。

4. 手写场景的特殊问题

大多数公式 OCR 模型是印刷优先的：im2latex-100k 全部是 LaTeX 渲染的印刷公式，pix2tex 的默认权重也主要在这类数据上训练。直接拿去识别手写，字符错误率会明显升高。CROHME 系列[2]是手写公式识别的标准基准，但数据量小（训练集约 1 万条表达式）且以在线笔迹为主；专门在 CROHME 上训练或微调的模型（以及 UniMERNet 这类混合了 HWE 域的模型）才对手写有较好覆盖。

可以预期的差距：印刷公式上主流模型的表达式级准确率（ExpRate，整条 LaTeX 完全正确）可以做到 90% 以上；CROHME 离线手写上，近年最好的专用模型 ExpRate 大致在 60%–70% 区间，泛化到真实手机拍摄的作业照片时会再降[5]。也就是说，每三张手写公式里就可能有一张需要人工核对——这个数字决定了为什么单靠本地 OCR 不能闭环。

典型失败模式（我们的微积分作业里都会遇到）

失败模式现象对 OCR 的影响
笔画粘连dx 写成一笔，e^x 的 e 与上标连在一起分割错误，整段输出乱序
上标 / 下标歧义手写时 x^2 的 2 只略微偏上；x_1 与 x1层级判断错，语义完全改变
积分限位置\int_0^1 上下限写在 ∫ 右侧、上方或挤在一起限被认成乘数或漏掉

6. 推荐的混合流水线

两类模型的失败模式几乎正交：公式 OCR 在感知上弱但绝不改写，VLM 在感知上强但可能改写。合理的做法不是二选一，而是让它们互为对照，只在分歧时升级。

几个实现要点：

  • 比较前先规范化。两个模型对同一公式可能给出 \frac{1}{2} 与 \dfrac{1}{2}、x^2 与 x^{2}、有无空格等表面差异。用一个小的 LaTeX 规范化函数（或先解析成 AST 再比较）避免假分歧。注意不要做代数化简——那会掩盖真正的差异。
  • VLM 的 prompt 要明确禁止修正。例如「逐字转写图中内容为 LaTeX，即使数学上有错误也保留原样，不要化简、不要补全、不要评价」。这能降低但不能消除过度纠正，所以仍需要 A 作为对照。
  • 把本地 OCR 的置信度当作免费信号。beam search 的 n-best 列表如果第一、二名分数接近，说明存在感知歧义（如 a vs \alpha），可以直接把两个候选都渲染给学生看。
  • 仲裁 prompt 限制选择空间。给强模型的任务是「在 A、B 之间选一个，或指出两者都错并给出逐字转写」，而不是开放式解题，减少它自由发挥的余地。
  • 永远不自动提交。与项目既定边界一致：任何路径的终点都是学生看到渲染后的公式并确认，再由学生自己在 WebAssign 上提交。

7. 在 Mac mini 上本地试用 Pix2Text 与 pix2tex

两者都是纯 pip 包，Apple Silicon 上用 CPU 或 MPS 即可。建议各建一个独立虚拟环境，避免 PyTorch / transformers 版本冲突。首次运行会自动下载模型权重（数百 MB）。

Pix2Text

包名 pix2text[4]。pip install "pix2text[multilingual]" 可加多语言文本 OCR；只做公式的话基础包即可。

pip install pix2text
from pix2text import Pix2Text

p2t = Pix2Text.from_config()              # 首次运行下载 MFD + MFR 权重
latex = p2t.recognize_formula("answer.jpg")  # 单张公式裁剪图 → LaTeX
print(latex)
page = p2t.recognize("page.jpg", file_type="page")  # 整页：检测 + 分块识别
print(page.to_markdown("out"))            # 文本 + $...$ 公式的 Markdown

pix2tex（LaTeX-OCR）

包名 pix2tex[3]。pip install "pix2tex[gui]" 会附带一个截图小工具；服务端用不到，装基础包即可。

pip install pix2tex
from PIL import Image
from pix2tex.cli import LatexOCR

model = LatexOCR()                        # 首次运行下载 ViT+decoder 权重
img = Image.open("formula.png").convert("RGB")
latex = model(img)                        # 返回 LaTeX 字符串
print(latex)

试用时的两个建议：先用打印出来的公式验证环境正常，再换手写；对手写样本至少收集 30–50 张自己的真实作业照片做人工对比，因为公开基准上的数字与手机拍摄的真实作业差距很大。若手写效果不够，下一步是 UniMERNet（pip install unimernet，权重更大，约 1 GB 级）[5]。

8. 术语表

编码器 / 解码器（encoder / decoder）
编码器把输入（图像）变成一组固定维度的特征向量；解码器在这些特征的条件下生成输出序列（LaTeX token）。两者之间通过交叉注意力（cross-attention）连接：解码器每生成一个 token，都会回头「看」编码器特征中相关的区域。
分词器（tokenizer）
把 LaTeX 字符串切成模型词表中的最小单元。公式 OCR 的词表通常是几百到几千个 LaTeX 命令与字符（\frac、^、{、x……）；VLM 用的是通用 BPE 词表（几万到几十万），LaTeX 命令会被拆成多个子词，这也是 VLM 更容易在 LaTeX 语法细节上出错的原因之一。
CTC vs. 自回归解码
CTC（Connectionist Temporal Classification）假设输出与输入在空间上单调对齐，一次性并行预测每个位置的字符，适合单行文本 OCR，但无法表达二维结构（分数、上下标）。自回归解码每步依赖前面已生成的 token，可以输出任意嵌套结构，因此公式识别几乎都用自回归；代价是慢，且可能陷入重复循环。
束搜索（beam search）
自回归解码时不只保留概率最高的一条序列，而是同时保留 k 条候选（beam width = k），每步扩展后再剪枝。最终得到 n-best 列表及各自的对数概率——第一名与第二名分数接近时，说明模型对这里存在歧义，可以作为「需要人工确认」的信号。
CROHME
Competition on Recognition of Online Handwritten Mathematical Expressions，自 2011 年起举办的手写公式识别竞赛与数据集[2]。以在线笔迹（带时间序列的坐标）为主，也提供渲染成位图的离线版本；是手写公式识别领域的标准基准，主要指标是 ExpRate（整条表达式完全正确的比例）。
